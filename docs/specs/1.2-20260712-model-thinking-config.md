# Spec 1.2：模型 Thinking 模式配置与 TUI 交互控制

| 字段 | 值 |
|------|-----|
| 状态 | draft |
| 日期 | 2026-07-12 |
| 风险级别 | 中 |

**风险说明：** 本 Spec 涉及：① 扩展 `LLMProvider` 接口参数（`stream()` 新增可选参数）；② 修改所有 provider 实现的请求体构建逻辑；③ 新增 TUI 状态管理和交互控制。不涉及外部鉴权、不修改渲染框架、不破坏现有通信协议，属"扩展已有接口 + 新增交互"场景，对应中级风险。

---

## 背景 / 目标 / 范围

### 背景

Spec 1.1 实现了 thinking 内容的接收与展示（Anthropic content block + OpenAI `reasoning_content` SSE 解析 → `StreamChunk.thinkingDelta` → TUI `ThinkingBlock`），但没有解决**如何向 API 请求 thinking 内容**的问题。

当前所有 provider 的请求体都是硬编码的固定字段，无法传递 thinking/reasoning 参数。而不同 provider 对 thinking 的支持方式差异很大，分为**启停（enable/disable）** 和 **强度（intensity）** 两个独立维度：

| Provider | 启停参数 | 强度参数 | 说明 |
|----------|---------|---------|------|
| **Anthropic** | `thinking.type: "enabled"` | `budget_tokens`（token 预算，≥1024） | 需显式启用，强度由 token 预算间接控制 |
| **DeepSeek** | `thinking.type: "enabled/disabled"` | — | 有启停开关，无强度参数 |
| **OpenAI o 系列** | 模型内置、无需启停 | `reasoning_effort: "low"/"medium"/"high"` | thinking 始终开启，只能调强度 |
| **部分国产/兼容层** | `enable_thinking: true` | 各厂商自定义 | 格式不统一 |
| **Ollama** | 因模型而异 | 因模型而异 | 通过 `extraBodyParams` 兜底 |

更关键的需求是：用户希望在 **TUI 运行过程中动态开启/关闭思考模式并调节强度**，而不是每次编辑 `settings.json`。

### 目标

1. 定义一个**与 provider 无关**的归一化 thinking 配置结构，各 provider 在内部映射为各自的 API 参数
2. 扩展 `LLMProvider.stream()` 接口，允许在调用时传入 thinking 参数
3. 在 TUI 中维护运行时 thinking 状态，提供快捷键切换交互
4. 保留 `extraBodyParams` 通用兜底机制，覆盖 provider 的任意特殊参数

### 包含

- `BaseProviderConfig` 新增 `extraBodyParams?: Record<string, unknown>` 字段
- `LLMProvider` 接口新增 `stream()` 的 `options` 参数（向后兼容）
- 各 provider 内部将归一化 `ThinkingConfig` 映射为各自的 API 参数格式
- `AgentRunner` 从 TUI 状态读取 thinking 配置并传入 `stream()`
- TUI 状态管理：运行时 thinking 开关与强度（不写入 `settings.json`）
- TUI 交互：状态栏指示器 + 快捷键切换
- Spec 4 修订：快捷键表追加 thinking 控制键、状态栏扩展

### 不包含

- thinking 内容的持久化存储（属 Spec 1.1 范围）
- 会话历史中记录 thinking 配置变更
- provider 切换时自动调整 thinking 参数（简化设计，用户手动切换）
- 可视化浮层/菜单选择强度（第一版用快捷键循环切换，后续可扩展）

---

## 技术方案

### 1. Provider 配置层：通用兜底参数

在 `src/agent/provider/types.ts` 的 `BaseProviderConfig` 追加：

```ts
interface BaseProviderConfig {
  id: string
  type: ProviderType
  label: string
  model: string
  apiKey?: string
  baseURL?: string
  /**
   * 透传给 API 请求体的额外参数。
   * 优先级低于 stream() 时传入的 ThinkingConfig（后者会覆盖同名键）。
   * 用于配置 thinking 参数等 provider 特定字段。
   */
  extraBodyParams?: Record<string, unknown>
}
```

**作用：** 用户在 `settings.json` 中可为每个 provider 预设基础 thinking 参数，运行时 TUI 控制在此基础上覆盖/启用。

> **安全注意：** `extraBodyParams` 可覆盖 `model`、`messages`、`stream` 等核心请求体字段。请用户谨慎填写——如需切换模型，应直接修改 provider 配置中的 `model` 字段，而非通过 `extraBodyParams` 注入。

```jsonc
{
  "providers": [
    {
      "id": "deepseek",
      "type": "openai-compat",
      "model": "deepseek-reasoner",
      "extraBodyParams": {
        "thinking": {"type": "enabled"}
      }
    }
  ]
}
```

### 2. Provider 接口扩展

#### 2.1 归一化 ThinkingConfig 类型

在 `src/agent/provider/types.ts` 新增：

```ts
/**
 * 与 provider 无关的归一化 thinking 配置。
 *
 * 包含两个正交维度：
 *   1. 启停（enabled）—— 是否开启 thinking
 *   2. 强度（effort）  —— 思考的深入程度
 *
 * 各 provider 在 stream() 内部根据自身 API 能力，只使用其支持的维度，
 * 不支持的维度直接忽略：
 *   - Anthropic: 使用 enabled + budgetTokens，忽略 effort（由 budgetTokens 间接控制强度）
 *   - DeepSeek:  使用 enabled，忽略 effort 和 budgetTokens
 *   - OpenAI o 系列： 忽略 enabled（始终开启），使用 effort → reasoning_effort
 *   - Ollama/其他: 走 extraBodyParams 兜底，本接口字段均不生效
 */
export interface ThinkingConfig {
  /** 是否启用 thinking 模式。
   *  - Anthropic: 为 true 时注入 thinking.type="enabled"
   *  - DeepSeek:  为 true 时注入 thinking.type="enabled"
   *  - OpenAI o 系列: 始终开启，该字段被忽略 */
  enabled: boolean
  /**
   * 思考强度/努力程度。
   * - low:  快速思考
   * - medium: 平衡模式
   * - high: 深度思考
   *
   * 不传时使用 provider 默认值。
   * 具体映射方式因 provider 而异：
   *   - OpenAI o 系列 → reasoning_effort
   *   - Anthropic → 不直接映射，由 budgetTokens 控制
   *   - DeepSeek → 忽略 */
  effort?: "low" | "medium" | "high"
  /**
   * thinking token 预算（仅 Anthropic 系使用）。
   * Anthropic API 要求 budget_tokens ≥ 1024，传入小于 1024 的值应抛出错误。
   * 不传时默认 1024（Anthropic API 最小值）。
   */
  budgetTokens?: number
}
```

#### 2.2 StreamOptions 参数

扩展 `stream()` 的第二个参数，保持向后兼容（现有调用不受影响）：

```ts
export interface StreamOptions {
  /** 用于取消请求的 AbortSignal */
  signal?: AbortSignal
  /** thinking 配置，不传表示使用 provider 默认行为 */
  thinking?: ThinkingConfig
}
```

#### 2.3 修订后的 LLMProvider 接口

```ts
export interface LLMProvider {
  readonly id: string
  readonly label: string
  readonly model: string
  stream(messages: ChatMessage[], options?: StreamOptions): AsyncIterable<StreamChunk>
}
```

**向后兼容说明：** 原签名 `stream(messages, signal?: AbortSignal)` 中的 `signal` 参数被纳入 `StreamOptions.signal`。所有调用方（4 个 test 文件、2 个 script 文件）需从 `(messages, signal)` 迁移至 `(messages, { signal })` 形式。`registry.ts` 不直接调用 `stream()`，无需修改。

### 3. Provider 内部映射规则

每个 provider 在 `stream()` 中根据 `thinking` 配置和 `extraBodyParams` 合并构建请求体。

#### 3.1 参数合并优先级规则

```
stream(messages, { thinking }) 中的 thinking config
  │ 覆盖（同名键）
  ▼
config.extraBodyParams
  │ 展开合并
  ▼
provider 默认构建的 body 字段（model, messages, stream 等）
```

即：**运行时参数 > 配置兜底 > 硬编码默认值**。

#### 3.2 AnthropicProvider

```ts
// 在构建 body 时：
const thinkingParam = options?.thinking
const extra = this.config.extraBodyParams ?? {}

// ⚠️ extraBodyParams 可覆盖 model/messages/stream 等核心字段，
// 请用户谨慎填写。如需修改 model，应直接修改 provider 配置中的 model 字段。
const bodyObj: Record<string, unknown> = {
  model: this.model,
  messages: ...,
  stream: true,
  ...extra,
}

// 运行时 thinking 配置覆盖
if (thinkingParam) {
  if (thinkingParam.enabled) {
    // Anthropic API 要求 budget_tokens ≥ 1024，且为必填字段
    const budgetTokens = thinkingParam.budgetTokens ?? 1024
    if (budgetTokens < 1024) {
      throw new Error("Anthropic Extended Thinking 的 budgetTokens 不能小于 1024")
    }
    bodyObj.thinking = {
      type: "enabled",
      budget_tokens: budgetTokens,
    }
  } else {
    // enabled=false 时移除 thinking 参数
    delete bodyObj.thinking
  }
}

const body = JSON.stringify(bodyObj)
```

#### 3.3 OpenAIProvider（type: "openai"）

OpenAI o 系列模型 thinking 始终开启，无需启停参数；`enabled` 字段被忽略，`effort` 映射为 `reasoning_effort`。

> **响应端解析：** OpenAI o 系列模型在 SSE 流中通过 `delta.reasoning_content` 字段返回 thinking 内容，该解析由 Spec 1.1 §3a 实现，与本节请求端配置（`reasoning_effort`）正交配合。详见 Spec 1.1 §3a。

```ts
const thinkingParam = options?.thinking
const extra = this.config.extraBodyParams ?? {}

const bodyObj: Record<string, unknown> = {
  model: this.model,
  messages: ...,
  stream: true,
  ...extra,
}

if (thinkingParam?.effort) {
  // OpenAI o 系列：effort → reasoning_effort
  bodyObj.reasoning_effort = thinkingParam.effort
}

const body = JSON.stringify(bodyObj)
```

#### 3.4 OpenAI-compat（type: "openai-compat"）

`openai-compat` 对应 DeepSeek 等兼容 OpenAI 协议但 thinking 参数格式不同的第三方 API。**不做 thinking 参数自动注入**——用户通过 `extraBodyParams` 在 settings.json 中自行配置：

```jsonc
{
  "id": "deepseek",
  "type": "openai-compat",
  "model": "deepseek-reasoner",
  "extraBodyParams": {
    "thinking": {"type": "enabled"}
  }
}
```

运行时 `ThinkingConfig.enabled` 仅控制是否应用 `extraBodyParams` 中的 thinking 相关参数，`effort` 字段被忽略：

```ts
const thinkingParam = options?.thinking
const extra = { ...this.config.extraBodyParams }  // 复制一份

const bodyObj: Record<string, unknown> = {
  model: this.model,
  messages: ...,
  stream: true,
  ...extra,
}

if (thinkingParam && !thinkingParam.enabled) {
  // 用户关闭 thinking 时，移除 extraBodyParams 中的 thinking 参数
  delete bodyObj.thinking
  delete bodyObj.enable_thinking
}

const body = JSON.stringify(bodyObj)
```

#### 3.5 AzureProvider

Azure OpenAI 复用 OpenAI 的 thinking 映射逻辑（`reasoning_effort`），但受部署区域和 `api-version` 限制，部分区域可能不支持。用户可酌情通过 `extraBodyParams` 覆盖。

#### 3.6 OllamaProvider

Ollama 的 thinking 支持因模型而异。原则上走 `extraBodyParams` 兜底，不做特化处理：

```ts
const bodyObj: Record<string, unknown> = {
  model: this.model,
  messages: ...,
  stream: true,
  ...this.config.extraBodyParams,
}

// Ollama 通常不需要 thinking 参数，如有需要用户通过 extraBodyParams 配置
```

### 4. 运行时 Thinking 状态

#### 4.1 状态定义

在 TUI 层（`src/App.tsx` 或独立 `useThinkingMode` hook）维护运行时状态。thinking 配置**按 provider ID 分别存储**，切换 provider 时自动恢复对应模型的上次配置：

```ts
/** 单个 provider 的 thinking 配置。 */
interface PerModelThinkingState {
  /** 是否启用 thinking */
  enabled: boolean
  /** 思考强度 */
  effort: "low" | "medium" | "high"
}

/**
 * 运行时 thinking 状态（按 provider ID 索引）。
 * key 为 ProviderConfig.id，每次切换 provider 时自动恢复。
 * 当某个 provider 首次使用且无记录时，使用默认值创建。
 */
type ThinkingStateMap = Record<string, PerModelThinkingState>
```

**默认值（首次使用某 provider 时）：**
- `enabled: true`（默认开启，符合"思考模式默认启用"原则）
- `effort: "medium"`（默认中等强度）

**状态作用域：** session 级别，不持久化到磁盘。TUI 关闭后所有 provider 的配置同时失效。

**行为规则：**
- 用户通过 `provider_changed` 事件（或 `/model switch`）切换 provider 时，`useThinkingMode` hook 从 `ThinkingStateMap` 中查找新 provider 的配置；找到则恢复，未找到则创建默认值
- Sidebar 始终显示当前 provider 的 thinking 状态
- provider 切换后，即使新 provider 不支持 thinking，已保存的配置仍然保留在 map 中（切换回来时恢复）

#### 4.2 与 AgentRunner 的交互

`AgentRunner.stream()` 接受当前 provider 的 thinking 配置参数：

```ts
// AgentRunner 内部
const currentThinking = thinkingStateMap[currentProviderId]
const streamOptions: StreamOptions = {
  signal,
  ...(currentThinking?.enabled && supportsThinking(providerType, model) ? {
    thinking: {
      enabled: true,
      effort: currentThinking.effort,
    }
  } : {}),
}

for await (const chunk of provider.stream(messages, streamOptions)) {
  // ...
}
```

### 5. TUI 交互设计

#### 5.1 Thinking 状态指示器

在 Sidebar 底部（provider 信息区域之后）追加 thinking 状态行，格式与 Spec 4 §4.1（Sidebar 布局）保持一致：

```
  provider: claude-sonnet-5
  model:    claude-sonnet-5
  thinking: on/med   ← 新增
```

| 状态 | 显示 | 说明 |
|------|------|------|
| thinking 开启 (medium) | `thinking: on/med` | **默认状态**（思考模式默认启用），`fg: sky` |
| thinking 开启 (low) | `thinking: on/low` | `fg: sky` |
| thinking 开启 (high) | `thinking: on/high` | `fg: sky` |
| thinking 关闭 | `thinking: off` | `fg: overlay0 dim` |
| 不支持 thinking | `thinking: --` | `fg: overlay0 dim`；当前 provider 型号不具备 thinking 能力时显示 |

spec 4 §9 更新：Sidebar 新增 thinking 状态行，最大显示宽度 20 字符，超长截断规则与 provider 行一致。

#### 5.2 `/model` 命令

通过 TUI 输入框的 `/model` 命令打开模型管理 Overlay，所有操作在 Overlay 内完成，无需记忆多个子命令。

**触发方式：** 在 `input` 焦点区输入 `/model` 后按 Enter，不发送 API 请求，而是打开一个模型管理 Overlay。

**Overlay 界面设计：**

```
┌─ 模型管理 ─────────────────────────────────┐
│  ○ anthropic-main   claude-sonnet-5         │
│    thinking: on/med  [t 切换]  [e 循环强度] │
│                                             │
│  ● openai-o3        o3-mini                 │
│    thinking: on/high [t 切换]  [e 循环强度] │
│                                             │
│  ○ deepseek         deepseek-reasoner       │
│    thinking: off     [t 切换]  [e 循环强度] │
│                                             │
│  ↑↓ 选择  Enter 切换  t 开关  e 强度  q 关闭│
└─────────────────────────────────────────────┘
```

当前选中的 provider 用 `●` 标记（其他用 `○`），选中行高亮显示。

**交互键（Overlay 内部）：**

| 键 | 操作 |
|----|------|
| `↑` / `↓` | 在 provider 列表中移动选中行 |
| `Enter` | 切换到当前选中的 provider |
| `t` | 切换当前选中行的 thinking 开关（on ↔ off） |
| `e` | 循环切换当前选中行的 effort 级别（low → medium → high → low） |
| `q` / `Esc` | 关闭 Overlay，不产生任何变更 |

**实现方式：**
- 复用 Spec 4 §12 定义的 `Overlay` 通用组件（与 `ProviderPicker` 同一套机制）
- 输入框匹配到 `/model` 命令时，阻止消息发送，改为触发 Overlay 打开
- Overlay 内的操作实时修改 `ThinkingStateMap`，Sidebar 同步刷新
- 切换到非当前 provider 时：调用 `providerRegistry.switchProvider(id)`，abort 当前 streaming（如有）
- 非 thinking 能力模型上按 `t` 时无操作（effort 行显示 `--`）
- Streaming 进行中：Overlay 内允许操作，Sidebar 显示 `(next)` 标记，变更对下次请求生效

### 6. 模型级别的 thinking 能力检测

thinking 能力不仅取决于 provider 类型，还取决于具体模型型号。定义一个辅助函数用于检测：

```ts
// src/agent/provider/types.ts 或独立的 utils 模块

/** 判断给定 provider 和模型名称是否支持 thinking 能力。 */
export function supportsThinking(providerType: ProviderType, model: string): boolean {
  switch (providerType) {
    case "anthropic":
      // Anthropic Extended Thinking 仅 claude-sonnet-5 及以上版本支持
      return /^claude-(sonnet|opus)-(?:[5-9]|\d{2,})/.test(model)
    case "openai":
      // OpenAI 仅 o 系列支持 reasoning_effort
      return /^o[1-9]/.test(model)
    case "openai-compat":
      // openai-compat（DeepSeek 等）因模型而异，假定支持（由 extraBodyParams 兜底）
      return true
    case "azure":
      // Azure OpenAI 的 thinking 支持取决于部署区域和 api-version
      return /^o[1-9]/.test(model)
    case "ollama":
      // Ollama 模型能力不透明，走 extraBodyParams 兜底，假定不支持避免误导
      return false
  }
}

> **维护说明：** 当新模型发布时，需同步更新此函数的正则匹配规则。建议将主流 thinking 支持的模型列表抽取为可配置的数据源。
```

该函数在以下场景使用：
- TUI 状态栏显示：返回 `false` 时指示器显示 `thinking: --`，快捷键无效
- `AgentRunner` 发起请求前：`supportsThinking` 返回 `false` 时即使 `thinkingMode.enabled === true` 也不传入 `ThinkingConfig`

### 7. API 错误处理

当 thinking 参数被 API 拒绝时（如模型不支持、参数格式错误），各 provider 应提供用户友好的错误信息：

| 场景 | 典型 HTTP 状态 | 建议的错误消息 |
|------|---------------|---------------|
| 向不支持 thinking 的 Anthropic 模型传入 `thinking` 参数 | 400 | "当前模型不支持 Extended Thinking，请更换为 claude-sonnet-5 或更高版本" |
| Anthropic `budget_tokens` 超出上限 | 400 | "thinking budget_tokens 超出上限，不能超过 max_tokens - 1000"（附带实际 max_tokens 值） |
| 向不支持 thinking 的 OpenAI 模型传入 `reasoning_effort` | 400 | "当前模型不支持 reasoning_effort 参数，请更换为 o 系列模型" |
| DeepSeek 等 openai-compat 模型 API 返回思考参数错误 | 400 | "API 返回错误：{原始错误信息}。请检查 extraBodyParams 中的 thinking 配置是否与当前模型匹配" |

**实现方式：** 在各 provider 的 `stream()` 方法中，当 `response.ok === false` 时，尝试解析 API 返回的 error body，匹配常见错误模式后返回上述中文错误消息。无法匹配的错误类型则透传原始错误信息。

## 回滚策略

- `extraBodyParams` 为可选字段，移除不影响现有配置加载（JSON 忽略未知字段）
- `StreamOptions` 为可选参数，各 provider 实现中简单 revert 为原有签名即可
- 各 provider 的 thinking 映射代码集中在各自文件中，可独立回滚
- `supportsThinking()` 为纯函数，移除不影响其他逻辑
- TUI 状态管理隔离在 `useThinkingMode` hook 中，移除不影响其他交互
- 快捷键为 `messages` / `input` 焦点区新增绑定，移除不破坏现有快捷键
