# Spec 1.1：模型 Thinking 内容支持

| 字段 | 值 |
|------|-----|
| 状态 | draft |
| 日期 | 2026-07-11 |
| 风险级别 | 中 |

> **风险说明：** 本 Spec 同时触及三层：① 扩展 `StreamChunk` 和 `AgentEvent` 协议（已在 Spec 2 中被多处引用）；② 修改 Anthropic provider SSE 解析器；③ 新增 UI 渲染组件。不涉及渲染框架变更，不引入外部鉴权，属"扩展已有通信协议 + 新增展示组件"场景，对应中级风险。

---

## 背景 / 目标 / 范围

### 背景

Anthropic 的 Extended Thinking 功能会在 SSE 流中产出独立的 `thinking` content block。当前 `AnthropicProvider` 的 SSE 解析器对此类 block 完全忽略：`content_block_start` 事件不区分 `type: "text"` 和 `type: "thinking"`，`content_block_delta` 也只提取 `delta.text`，跳过 `delta.thinking`。数据通道（`StreamChunk` / `AgentEvent`）亦没有为 thinking 内容预留字段。

其他支持 thinking 的 provider（如 OpenAI `o1/o3`、DeepSeek-R1）未来也可能走相同通路。

### 目标

1. 扩展 `StreamChunk` 和 `AgentEvent` 以承载 thinking delta
2. 修订 `AnthropicProvider` SSE 解析器，正确提取 thinking content block
3. 定义 thinking 内容在 TUI 中的视觉呈现（可折叠的折叠块）
4. 通过 `settings.json` 的 `showThinking` 开关控制是否展示

### 包含

- `StreamChunk` 新增 `thinkingDelta` 字段（可选）
- `AgentEvent` 新增 `stream_thinking_chunk` 和 `stream_thinking_done` 事件
- `AnthropicProvider.parseAnthropicStream()` 修订：追踪当前活跃 content block 类型
- `ThinkingBlock` TUI 渲染组件（折叠/展开交互）
- `MessageItem` 修订：在助手消息正文前条件渲染 `ThinkingBlock`
- `PawSettings` 新增可选字段 `showThinking: boolean`（默认 `true`）
- Spec 2 `AgentEvent` 附录追加新事件类型记录
- 视觉设计文档追加 `ThinkingBlock` 样式规范

### 不包含

- Azure / Ollama provider 的 thinking 解析（各 provider 格式差异较大，独立支持）
- thinking 内容的持久化存储（当前 session 内有效）
- thinking token 计量与费用统计
- 在 `ConversationHistory` 中保留 thinking 内容用于上下文回注（需 Anthropic API 支持，另行研究）

## 技术方案

### 1. `StreamChunk` 扩展

在 `src/agent/provider/types.ts` 中为 `StreamChunk` 追加可选字段：

```ts
export interface StreamChunk {
  delta: string           // 正文 delta（thinking block 激活时为空字符串）
  done: boolean
  stopReason?: "stop" | "tool_use"
  thinkingDelta?: string  // 仅在 thinking block 激活且有内容时存在
}
```

约束：同一个 `StreamChunk` 中 `delta` 与 `thinkingDelta` 互斥——thinking block 激活期间产出的 chunk 只填 `thinkingDelta`，`delta` 为空字符串；text block 激活时只填 `delta`，不含 `thinkingDelta`。

### 2. `AgentEvent` 新增类型

在 `src/agent/events.ts` 追加（不修改已有事件）：

```ts
/** 接收到一段 thinking 增量文本 */
export interface StreamThinkingChunkEvent {
  type: "stream_thinking_chunk"
  /**
   * 含 messageId 是因为 stream_chunk 暂无此字段（历史设计）。
   * 若后续 stream_chunk 引入 messageId，两者可统一设计。
   */
  payload: { delta: string; messageId: string }
}

/** thinking 内容完整接收完毕（包括 abort 时的部分内容） */
export interface StreamThinkingDoneEvent {
  type: "stream_thinking_done"
  payload: { totalThinking: string; messageId: string }
}
```

`AgentRunner` 的职责（对应 Spec 2 §3 核心循环）：
- 收到含 `thinkingDelta` 的 `StreamChunk` 时，额外 emit `stream_thinking_chunk`
- 收到 `done === true` 且 `stopReason === "stop"` 时，若存在累积的 thinking 文本，emit `stream_thinking_done`

> **P0-01 合规**：两个新类型只追加到联合类型 `AgentEvent`，不修改现有成员。

### 3. `AnthropicProvider` SSE 解析器修订

`content_block_start` 事件会携带 `{ index, content_block: { type, ... } }`，需追踪当前活跃 block 的类型。

修订后的状态变量：

```ts
// parseAnthropicStream() 内部新增
// 注意：当前实现假设 Anthropic SSE 中各 content block 严格顺序，
// 不存在交错（即 block_N_stop 一定先于 block_N+1_start）。
// 若 Anthropic 将来支持并发 block，需改为 Map<index, type>。
let activeBlockType: "text" | "thinking" | null = null
```

事件处理修订：

```ts
case "content_block_start": {
  const blockStart = evt.data as {
    content_block?: { type?: string }
  }
  activeBlockType = (blockStart.content_block?.type === "thinking")
    ? "thinking"
    : "text"
  break
}

case "content_block_delta": {
  const delta = evt.data as {
    delta?: { type?: string; text?: string; thinking?: string }
  }
  if (activeBlockType === "thinking") {
    const thinking = delta.delta?.thinking
    if (thinking) {
      yield { delta: "", done: false, thinkingDelta: thinking }
    }
  } else {
    const text = delta.delta?.text
    if (text) {
      yield { delta: text, done: false }
    }
  }
  break
}

case "content_block_stop": {
  activeBlockType = null
  break
}
```

### 3a. OpenAI `reasoning_content` 解析

OpenAI o 系列模型在 SSE 流中通过 `delta.reasoning_content` 字段返回 thinking 内容，与 `delta.content` 同级。与 Anthropic 的 content block 机制不同，OpenAI 没有独立的 block start/stop 事件，thinking 的启停通过字段值隐式表达：

| SSE chunk | 含义 |
|-----------|------|
| `"delta": {"content":"","reasoning_content":"..."}` | thinking 进行中，`content` 为空 |
| `"delta": {"content":"","reasoning_content":null}` | thinking 结束，后续 chunks 将出现正常 `content` |
| `"delta": {"content":"..."}` | 正常文本输出（`reasoning_content` 不再出现） |

修订后的 `parseStream()` 解析逻辑：

```ts
const deltaContent = choice?.delta?.content ?? ""
const reasoningContent = choice?.delta?.reasoning_content
const finishReason = choice?.finish_reason ?? null

// 处理 reasoning_content（OpenAI o 系列模型的 thinking 内容）
if (reasoningContent && typeof reasoningContent === "string") {
  yield { delta: "", done: false, thinkingDelta: reasoningContent }
}

// 处理普通正文 delta
if (deltaContent) {
  yield { delta: deltaContent, done: false }
}

// 当 finish_reason 存在时，stream 结束
if (finishReason) {
  yield { delta: "", done: true, stopReason: ... }
  return
}
```

约束与 Spec 1.1 §1 保持一致：同一 `StreamChunk` 中 `delta` 与 `thinkingDelta` 互斥。OpenAI 的输出天然满足此约束——`reasoning_content` 非空时 `content` 为空字符串，反之亦然。

向后兼容：不含 `reasoning_content` 的普通流行为与修改前完全一致（`reasoning_content` 为 `undefined`，条件判断跳过）。

> **与 Spec 1.2 的关联：** Spec 1.2 定义了 `ThinkingConfig.effort` → `reasoning_effort` 的请求端映射。本节的 `reasoning_content` 解析是**响应端**处理，两者正交且相配合。同时配置 Spec 1.2 的 `reasoning_effort` 和本节解析，即可在 TUI 中完整支持 OpenAI o 系列模型的 thinking 交互。

### 5. TUI 消息渲染

#### 5.1 消息数据结构扩展

Spec 4 §4.1 中 `ChatMessage` 扩展以下字段：

```ts
type ChatMessage = {
  id: string
  role: MessageRole
  text: string
  streamingText?: string
  isStreaming: boolean
  createdAt: number
  thinking?: string           // thinking 完整内容（stream_thinking_done 后写入）
  streamingThinking?: string  // thinking 增量缓冲（stream_thinking_chunk 期间）
  isThinkingStreaming?: boolean // 默认 undefined / false
  isThinkingExpanded?: boolean // 用户展开/折叠状态，默认 undefined / false
}
```

#### 5.2 `ThinkingBlock` 组件

新增组件 `src/components/ThinkingBlock.tsx`：

```
props:
  thinking: string          // 完整 thinking 内容
  streamingThinking?: string
  isStreaming: boolean      // thinking 是否仍在流式接收中
  isExpanded: boolean       // 受控展开状态
  onToggle: () => void      // 展开/折叠回调
```

渲染形态（折叠）：

```
[thinking  v]   按 t 展开
```

渲染形态（展开）：

```
[thinking  ^]   按 t 折叠
 正在思考如何分解这个问题...
 首先需要理解用户的需求，然后...
```

- 折叠时只显示标题行；展开时在标题行下方渲染 thinking 内容（纯文本，不做 Markdown 解析）
- streaming 进行中，标题行前缀改为 Braille loading 字符（与 §7.2 共用动画规范）
- streaming 完成后显示总字数提示：`[thinking  v]  (1024 chars)`

#### 5.3 `MessageItem` 修订

`MessageItem` 渲染顺序：

```
MessageHeader   [role 标签 + 时间戳]
ThinkingBlock   [仅当 message.thinking || message.streamingThinking 存在，且 showThinking === true]
MessageBody     [正文]
```

#### 5.4 快捷键

在 `messages` 焦点区：按 `t` 键切换**最近一条**含 thinking 内容的助手消息的 `isThinkingExpanded` 状态。

**操作目标定义**：`t` 键的目标消息固定为消息列表中**最后一条 role 为 `assistant` 且含 `thinking` 内容的消息**（即 `thinking` 字段非空）。若消息列表中不存在这样的消息，`t` 键无操作。

> 此方案（方案 A：固定最后一条 assistant thinking 消息）是 Spec 1.1 阶段的最小实现。方案 B（messages 区增加消息级游标，`t` 键作用于游标所在消息）留待后续 Spec 扩展，届时同步修订 Spec 4 §2.3 焦点管理和 §3 快捷键表。

此快捷键补充到 Spec 4 §3 全局快捷键表（已修订）。

### 6. 事件消费流程

UI 层新增消费规则（对应 Spec 4 §8 AgentEvent 消费规则表）：

| type | payload | 消费方式 |
|------|---------|---------|
| `stream_thinking_chunk` | `{ delta: string; messageId: string }` | 追加至对应消息的 `streamingThinking`，`isThinkingStreaming: true` |
| `stream_thinking_done` | `{ totalThinking: string; messageId: string }` | 写入 `thinking`，清空 `streamingThinking`，`isThinkingStreaming: false` |

### 7. `AgentRunner` 内部处理逻辑

> **本节同时修订 Spec 2 §4 核心循环 step 6**：原文"若 `done === false`：emit `StreamChunkEvent { delta }`"修订为"若 `delta` 非空时 emit"（空 delta 在 thinking block 激活期间产出，不应透传给 UI）。这是行为变更，原实现如有空 delta emit 逻辑需同步调整。

核心循环中新增累积逻辑（对应 Spec 2 §4 核心循环 step 6）：

```
├─ 每收到 StreamChunk：
│    ├─ 若含 thinkingDelta（且 thinkingDelta 非空）：
│    │    emit stream_thinking_chunk { delta: thinkingDelta, messageId: replyId }
│    │    并累积到 accumulatedThinking
│    ├─ 若 delta 非空（text 内容）：
│    │    emit stream_chunk { delta }（非空时才 emit，与原逻辑一致）
│    │    并累积到 accumulatedText
│    └─ 若 done === true：
│         若 accumulatedThinking 非空：
│           emit stream_thinking_done { totalThinking: accumulatedThinking, messageId: replyId }
│         emit stream_done { totalText, stopReason }（原有逻辑不变）
│
└─ 若抛出异常：
     ├─ 若 AbortError（用户主动中止）：
     │    若 accumulatedThinking 非空：                    ← Spec 1.1 新增
     │      emit stream_thinking_done {                    ← 先关闭 thinking 状态，避免 UI 泄漏
     │        totalThinking: accumulatedThinking,
     │        messageId: replyId
     │      }
     │    emit AgentAbortEvent { messageId: replyId, partialText: accumulatedText }
     └─ 其他错误：
          emit StreamErrorEvent { kind, message }
          （不追加历史，下次请求重试）
```

**abort 时 thinking 处理说明**：AbortError 发生时若 thinking 流尚未完成，需先 emit `stream_thinking_done`（携带已累积的部分 thinking），再 emit `agent_abort`，保证 UI 端 `isThinkingStreaming` 能从 `true` 正确归零，不出现永久 loading 动画。

## 验收标准

- [ ] `StreamChunk` 类型含可选 `thinkingDelta` 字段，`bunx tsc --noEmit` 通过
- [ ] `AgentEvent` 联合类型包含 `stream_thinking_chunk` 和 `stream_thinking_done`
- [ ] `AnthropicProvider` 对含 thinking block 的 SSE 流正确产出带 `thinkingDelta` 的 `StreamChunk`
- [ ] `AnthropicProvider` 对不含 thinking block 的普通流，产出的 `StreamChunk` 不含 `thinkingDelta`（向后兼容）
- [ ] `AgentRunner` 收到含 `thinkingDelta` 的 chunk 时，emit `stream_thinking_chunk` 事件
- [ ] `AgentRunner` 在 `stream_done` 前 emit `stream_thinking_done`（若存在 thinking）
- [ ] `showThinking: false` 时，TUI 不渲染 `ThinkingBlock`，但事件仍正常 emit（数据层与展示层分离）
- [ ] thinking streaming 进行中，`ThinkingBlock` 标题行前缀显示 Braille loading 动画
- [ ] thinking streaming 完成后，`ThinkingBlock` 默认折叠，标题行显示字数提示
- [ ] 在 `messages` 焦点区按 `t` 键可展开/折叠含 thinking 的助手消息
- [ ] 展开状态下，thinking 内容完整显示，无截断
- [ ] 无 thinking 内容的消息渲染不受影响（`ThinkingBlock` 不渲染）
- [ ] `bunx tsc --noEmit` 通过

## 回滚策略

- `StreamChunk.thinkingDelta` 为可选字段，移除不影响现有 provider 实现
- `AgentEvent` 新增的两个类型只是追加，移除不影响现有消费方
- `AnthropicProvider` 修订可独立回滚：将 `content_block_start` 和 `content_block_stop` 处理还原为 `break`，`content_block_delta` 还原为只读 `delta.text`
- `ThinkingBlock` 组件独立文件，删除即可；`MessageItem` 修订仅添加了一个条件渲染，移除不破坏现有消息渲染
- `PawSettings.showThinking` 为可选字段，移除不影响配置加载（JSON 解析忽略未知字段）
